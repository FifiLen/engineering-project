# 11. Ryzyka i dług techniczny

| Ryzyko | Wpływ | Działanie |
|---|---|---|
| Rozrost zakresu przy jednym autorze | Wysoki | Iteracje z działającym demem, rozszerzenia oznaczone jako opcjonalne |
| Limity publicznych usług mapowych (Photon, OpenFreeMap) | Średni | Adaptery z możliwością podmiany, OSRM hostowany samodzielnie |
| Dostępność BLIK w trybie testowym | Niski | Sprawdzone przy ADR 0050: BLIK działa w trybie testowym Stripe dla PLN; `STRIPE_BLIK=false` ukrywa go w aplikacji |
| Zależność od operatora płatności (Stripe) | Średni | Port `PaymentProvider` z atrapą w procesie: testy, CI i demo działają bez sieci i kluczy ([ADR 0050](../adr/0050-integracja-stripe.md)) |
| Webhooki Stripe lokalnie wymagają Stripe CLI | Niski | Bez `stripe listen` płatności rozstrzyga sprawdzenie statusu po 2 min (`payments.reconcile`) |
| Atrapa operatora może się rozjechać ze Stripe | Niski | Te same zdarzenia, kody odmów i podpis w formacie `Stripe-Signature`; scenariusz demo przechodzi też na Stripe po wpisaniu kluczy |
| Stan atrapy w pamięci API | Niski | Po restarcie API płatności atrapy w toku kończą się odmową przy sprawdzeniu statusu; dotyczy tylko środowiska deweloperskiego |
| Płatności w natywnej aplikacji niesprawdzone (development build) | Średni | Ten sam dług co przy mapie: implementacja natywna przechodzi typy i lint, ekrany sprawdzane w wersji web na atrapie ([ADR 0051](../adr/0051-platnosci-w-aplikacji.md)) |
| Ujemne saldo po przejeździe droższym niż saldo | Niski | Ujemne saldo blokuje kolejny start do doładowania (pytanie 4); w produkcji ryzyko nieściągalnej kwoty |
| Paragon niefiskalny i robocza stawka VAT | Średni | Opis drogi do kasy fiskalnej online w §8.4; stawka VAT jako pole wersji cennika do zmiany bez kodu |
| Broker MQTT jako pojedynczy punkt awarii | Średni | Akceptowane w projekcie; opis klastrowania jako kierunek rozwoju |
| Pamięć OSRM na małym VPS | Niski | Wycinek tylko jednego województwa |
| Różnice między symulatorem a prawdziwym urządzeniem | Średni | Kontrakt MQTT w AsyncAPI jako jedyne źródło prawdy o protokole |
| Brak dostawcy SMS i poczty | Średni | Bramka SMS i link zaproszenia za adapterami; w środowisku deweloperskim kod w logu API, link pokazany raz w panelu ([ADR 0035](../adr/0035-sesje-tokeny-i-straznik-uprawnien.md)) |
| Pamięć podręczna uprawnień w jednej instancji API | Niski | Zmiana ról działa od razu w tej instancji, w pozostałych po 10 s; dezaktywacja odcina dostęp przy następnym odczycie |
| Jedna instancja backendu (stały identyfikator klienta MQTT, bufor telemetrii w pamięci) | Niski | Skalowanie przez subskrypcje współdzielone MQTT; opisane w [ADR 0033](../adr/0033-telemetria-i-status-floty.md) |
| Natywna mapa w aplikacji niesprawdzona (brak Xcode i Android SDK na komputerze autora) | Średni | Mapa w dwóch implementacjach ze wspólnym interfejsem; wersja web sprawdzana w każdej iteracji, development build do zbudowania po instalacji Xcode ([ADR 0040](../adr/0040-mapa-lokalizacja-aparat-w-aplikacji.md)) |
| Zegar urządzenia a termin `expiresAt` komendy | Niski | W projekcie zegar symulatora i backendu jest wspólny; dla prawdziwego sprzętu tolerancja albo czas względny ([ADR 0038](../adr/0038-wygasanie-komend-mqtt.md)) |
| Limit potwierdzenia zależy od odpytywania kolejki pg-boss | Niski | `UNLOCK_FAILED` po 10–11 s zamiast dokładnie 10 s; odpytywanie co 1 s ([ADR 0037](../adr/0037-pg-boss-konfiguracja-i-zadania.md)) |
| Dokładność GPS na granicy strefy | Niski | Histereza wyjazdu (2 odczyty albo 10 m) i komunikat z opóźnieniem do jednego odczytu (5 s); prawdziwy sprzęt miałby geofencing w urządzeniu ([ADR 0043](../adr/0043-wykrywanie-zmian-stref.md)) |
| Publiczny Photon w demo wyszukiwania | Niski | Pamięć podręczna 24 h, limit 30 zapytań na minutę na klienta, wariant błędu w aplikacji; własny kontener to zmiana `PHOTON_URL` ([ADR 0045](../adr/0045-wyszukiwanie-miejsc-photon.md)) |
| Dwa procesy OSRM (rower i pieszo) | Niski | Około 1 GB pamięci i 1,6 GB danych na komputerze dewelopera; bez OSRM linia prosta ([ADR 0048](../adr/0048-trasy-dla-klienta-z-osrm.md)) |
| Expo Push bez urządzenia i projektu EAS | Średni | Bramka `PushGateway` z atrapą (`PUSH_PROVIDER=fake`): wpis `SENT`, treść w logu API i baner w wersji web przez `notification.created`. Bez `projectId` z `eas init` aplikacja nie pobiera tokenu (bez błędu). Prawdziwy push wymaga development build, poświadczeń FCM i APNs; ścieżka Expo ma tylko testy z atrapą klienta HTTP ([ADR 0058](../adr/0058-powiadomienia-push-z-szablonow.md)) |
| Atrapa powiadomień pokazuje stan bramki, nie telefonu | Niski | Lista „Wysłane” w demo ma `SENT` bez dostarczenia; potwierdzenia (`notification.receipts`) działają dopiero z Expo |
| Pliki przechodzą przez proces API | Niski | Zdjęcia po kompresji w aplikacji (1600 px, JPEG 0,7) mają kilkaset KB, limit 10 MB; powrót do podpisanego adresu S3 nie zmienia modelu danych ([ADR 0057](../adr/0057-pliki-zdjecia.md)) |
| Podpisany adres odczytu pliku działa 10 min po przekazaniu | Niski | Krótki czas, zdjęcia hulajnóg bez danych osobowych; adres wystawia się tylko temu, kto ma dostęp do rekordu |
| Aparat i wybór zdjęć niesprawdzone natywnie | Średni | Ten sam dług co mapa i płatności: ekrany zdjęcia sprawdzane w wersji web (wybór pliku), development build do zbudowania |
| Zakończenie bez łączności i jazda po żądaniu | Średni | Klient może zakończyć w strefie i jechać dalej bez sieci. Ograniczają to `lock` po powrocie łączności (także dla hulajnogi bez przejazdu), wymagane zdjęcie i zdarzenie `MOVED_AFTER_END` (ponad 200 m), ale kwota nie koryguje się sama; decyzja należy do dyspozytora ([ADR 0056](../adr/0056-przejazd-bez-lacznosci-i-niska-bateria.md)) |
| Przejazd w `ENDING` do 10 min | Niski | Klient nie zacznie nowego przejazdu, dopóki blokada nie przyjdzie albo nie minie 10 min (`END_UNCONFIRMED` ze zgłoszeniem `OFFLINE`); limit potwierdzenia komend liczony od `expiresAt`, nie od wysłania |
| Hulajnoga, która nie wróci po `END_UNCONFIRMED` | Niski | Zostaje odblokowana; zgłoszenie `OFFLINE` trafia do serwisu, a po powrocie łączności system wysyła `lock` |
| Automatyczne zamknięcie zgłoszenia `OFFLINE` ukrywa hulajnogę, która często traci sieć | Niski | Raport awaryjności (iteracja 8) liczy także zamknięte zgłoszenia ([ADR 0055](../adr/0055-zgloszenia-i-proces-serwisowy.md)) |
| Kwalifikacja opłaty za odholowanie jako kary umownej | Średni | Opłata jest pozycją poza VAT ([ADR 0061](../adr/0061-oplata-za-odholowanie-jako-kara-umowna.md)); regulamin musi nazywać ją karą umowną za pozostawienie hulajnogi poza strefą, a ostateczną ocenę podatkową zostawiamy księgowości. Zwrot dzielony proporcjonalnie może skorygować opłatę także przy zwrocie dotyczącym tylko przejazdu |
| Opłata za odholowanie z nieaktualnej pozycji | Niski | Okno zdalnego zakończenia pokazuje wiek ostatniej pozycji, a operator decyduje o opłacie przy każdym przypadku |
| Polecenia symulatora z anonimowego brokera | Niski | Lokalnie każdy klient brokera może opublikować `simulator/control`; ochronę daje `simulator.manage` w API, a demo wymaga ACL brokera. `SIMULATOR_CONTROL_ENABLED` domyślnie tylko przy `NODE_ENV=development` ([ADR 0059](../adr/0059-symulator-sterowany-z-panelu.md)) |
| Dwa źródła poleceń symulatora (plik i MQTT) | Niski | Wygrywa ostatnie polecenie; panel pokazuje stan z `simulator/status`, więc rozbieżność jest widoczna |
| Wyniki poleceń symulatora tylko w pamięci API | Niski | Po restarcie API ostatnie polecenia z dziennika audytu nie mają wyniku („Bez wyniku”) |
| Dwie reguły „poniżej minimum” w bazie | Niski | Core i `v_spare_part_list` liczą `<`, a starszy widok `v_low_stock_parts` z migracji 0002 liczy `<=`; do ujednolicenia przy raporcie części (iteracja 8) |
| Gotenberg 9 to młoda linia z wydaniami co 1–2 dni | Średni | Przypięta wersja 9.5.1 (skrót obrazu), test integracyjny `gotenberg.integration.test.ts` przy dostępnym `GOTENBERG_URL` (konwersja i liczba stron); zmiana wersji tylko z testem. 9.5.1 nie ma limitów pamięci silników, więc chroni `mem_limit` kontenera i `GOMEMLIMIT` ([ADR 0066](../adr/0066-silnik-dokumentow-gotenberg-i-zadania.md)) |
| LibreOffice układa dokument inaczej niż Word | Średni | Szablony startowe z Inter sprawdzone w PDF z Gotenberga (każdy na 1 stronie z danymi przykładowymi); podgląd PDF wersji przed aktywacją pokazuje wynik silnika, nie Worda |
| Szablon zepsuty w Wordzie (znacznik rozbity, literówka, pętla bez zamknięcia) | Niski | Walidacja przy wgraniu z miejscem błędu i listą dostępnych pól; wersja z błędem nie powstaje, a aktywna zostaje bez zmian ([ADR 0067](../adr/0067-szablony-wydrukow-docx.md)) |
| Surowy XML w szablonie (`{@…}` docxtemplater, zmiana ograniczników) | Niski | Inspekcja wszystkich części i elementów tekstu, które szablonuje docxtemplater, a przy wypełnianiu `templateGuardModule` i wyłączona zmiana ograniczników (poprawka D2 po przeglądzie); nowa wersja docxtemplater wymaga ponownego sprawdzenia `templatedFiles` i `tagsXmlTextArray` |
| Wydruk z danymi klienta pobrany przez operatora bez `users.read` | Niski | Flaga `customer_data_visible` przy wierszu i `users.read` przy pobraniu, szczegółach i ponowieniu (migracja 0012, test e2e); wiersze sprzed migracji z rodzajów z polami klienta mają flagę ustawioną |
| Eksport danych bez zdjęć | Niski | Zdjęcia parkowania i zgłoszeń są w pliku tylko jako metadane; czy to wyczerpuje prawo do przenoszenia danych, ocenia autor. Rozszerzenie nie zmienia tabeli ([ADR 0069](../adr/0069-eksport-danych-klienta.md)) |
| Zakres eksportu przy nowych tabelach z danymi klienta | Niski | Test sprawdza sekcje ze schematu eksportu, ale nie wykryje nowej tabeli bez sekcji; nowy moduł z danymi klienta rejestruje port w `DataExportRegistry` |
| Redaktor może opublikować regulamin | Średni | Dokumenty prawne zostają przy `content.write` (pytanie 7), więc publikacja wersji przez Redaktora wymusza ponowną akceptację u wszystkich klientów. Jeśli autor uzna to za zbyt szerokie, osobne uprawnienie publikacji wprowadzi nowy ADR ([ADR 0062](../adr/0062-modul-tresci-sekcje-publikacja-dane-firmy.md)) |
| Grafika hero 760 px na ekranach 2× | Niski | Rendery w repozytorium mają 767–922 px, więc minimum obniżone z 1200 do 760 px ([ADR 0070](../adr/0070-minimalna-szerokosc-grafiki-hero.md)); obraz może być mniej ostry na ekranach o dużej gęstości, a grafika Open Graph poniżej 1200 px może być małą miniaturą. Próg podniesie kolejny ADR po szerszych renderach |
| Cache strony lokalny dla instancji `next start` | Niski | Odświeżenie na żądanie trafia do jednej instancji, pozostałe pokażą zmianę po 5 min; przy kilku instancjach wspólny `cacheHandler` ([ADR 0065](../adr/0065-strona-promocyjna-z-tresci.md)) |
| Grafiki biblioteki przez proces API, bez CDN i skalowania | Niski | Długi cache `immutable` po stronie przeglądarki i aplikacji, ostrzeżenie powyżej 2560 px; w produkcji serwer pośredniczący z cache przed API ([ADR 0064](../adr/0064-biblioteka-mediow.md)) |
| Własny parser Markdown to nie pełny CommonMark | Niski | Wąski podzbiór z testami w `packages/shared`; treść wpisana poza API z zabronioną konstrukcją pokaże się jako tekst z pominiętymi wierszami ([ADR 0063](../adr/0063-markdown-w-tresciach.md)) |
| Zadanie wydruku albo eksportu porzucone po restarcie API | Niski | Ponowienie przejmuje wiersz `RUNNING` starszy niż limit zadania, a `documents.sweep` i `data-exports.sweep` (co 5 min) kończą porzucone po 15 i 30 min (poprawka D3 po przeglądzie) |
| Paragon PDF i eksport danych niesprawdzone natywnie | Średni | Ten sam dług co mapa i aparat: pobranie (`expo-file-system`), udostępnienie (`expo-sharing`) i podgląd sprawdzone tylko w wersji web, development build do zbudowania |
| Przejazdy z iteracji 3 i 4 bez obciążenia portfela | Niski | Zostają nierozliczone (stan rozliczenia `NONE`, pytanie 12); nowe przykładowe przejazdy w danych startowych są rozliczone z portfela ([ADR 0049](../adr/0049-rozliczenie-przejazdu.md)) |

Dług techniczny jest dopisywany w dzienniku w chwili, gdy świadomie go zaciągamy.
